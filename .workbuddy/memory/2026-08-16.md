## 书签导航（booknav）机制 & 图标来源
- 配置：`src/config/booknavConfig.ts`。`booknavConfig` 是 `BooknavGroup[]`，每组含 `id/name/icon/desc/weight/enabled/items[]`；`items` 每项 `title/url/desc?/icon?/weight?/enabled?`。分组与条目均按 `weight` 降序；`enabled:false` 可隐藏。页面 `/booknav/`，由 `siteConfig.pages.booknav` 控制开关。
- 图标解析（`src/utils/booknav-utils.ts` `resolveBooknavIcon`）：手填 `icon` 优先 → 否则 auto-favicon → 最后首字母兜底（`<img>` onerror 也会降级为首字母）。
  - `icon` 三种写法：`namespace:name`（astro-icon 图标名，走 `<Icon>`）、`http(s)://` 或 `/` 开头（`<img>` 图片）、其他当作图片路径。
  - 自动 favicon：`booknavPageConfig.favicon.api="https://a.favicon.im/{domain}"`，用 URL 域名替换 `{domain}`。
- 关键坑：astro-icon 是**本地打包图标集**，**不是**运行时拉 Iconify API。可用集合在 `astro.config.mjs` 的 `icon({ include: {...} })` 写死：`material-symbols / fa7-brands / fa7-regular / fa7-solid / simple-icons / mdi / mingcute`。（`@iconify-json/svg-spinners` 装了但没进 include，仅供 svelte 侧用。）想用新集合必须：① `pnpm add -D @iconify-json/<集合名>` ② 在 include 里加 `"<集合名>": ["*"]`，否则构建时图标缺失/报错。导航栏 `navBarConfig` 的图标用的是同一套 astro-icon 机制。
- 获取图标名：去 https://icon-sets.iconify.design 搜，复制 `集合:图标名`；书签场景优先 `simple-icons`（品牌 logo 全）或 `fa7-brands`。

## 修复：HomeHeroVideo 资源导入 dev 模式 404（[object Object]）
- 现象：用户刷新首页时 Network 出现 `http://localhost:4321/[object%20Object]` 404，且伴随 `_image` 端点请求。
- 根因：`HomeHeroVideo.astro` 里 `import hf22Video from "...mp4"` 和 `import hf21Poster from "...jpg"` 后直接 `as string`。Astro/Vite 在 **dev** 模式下对本地图片/视频 import 返回的是 `{ src, width, height, ... }` 对象（build 时才会内联成字符串），于是对象被 toString 成 `[object Object]` 传给 `<img src>`、`<video poster>` 和 `define:vars`，浏览器请求 `[object%20Object]` 报 404。
- 修复：在 `HomeHeroVideo.astro` 增加 `resolveAssetUrl(input)` helper，兼容 `string` 和 `{ src } / { default }` 对象，统一提取字符串 URL 后再传给模板和 `<script define:vars>`。
- 验证：`pnpm type-check`、`pnpm build` 通过；dev 首页 HTML 中 `videoUrl` 为 `"/src/assets/images/DesktopWallpaper/hf_22.mp4"`，`<img src>` / `<video poster>` 为 `"/@fs/D:/blog/Firefly/src/assets/images/DesktopWallpaper/hf_21.jpg?origWidth=800&..."`，不再含 `object%20Object`。

## 修复：HomeHeroVideo 视频不显示（is:inline 脚本混用 TS 语法）
- 现象：hf_21.jpg 能加载，但视频层不显示，只看得到下面的轮播图。控制台无报错（静默失败）。
- 根因：`HomeHeroVideo.astro` 的 `<script is:inline>` 里写了 `as HTMLVideoElement | null`、`let rafId: number | null`、`video!.duration` 等 **TypeScript 语法**。Astro 对 `is:inline` 脚本**不做 TS 编译**，原样输出到 HTML，浏览器解析即抛 `SyntaxError`，整个 IIFE 不执行 → `sync()` 没跑 → `#home-hero-video` 始终 `display:none`。坑：`tsc` 能过、`pnpm build` 不报错（构建期不编译 is:inline），但浏览器运行时炸。
- 修复：把该 `is:inline` 脚本改写为纯 JS（移除所有类型断言 `as`、非空断言 `!`、类型注解 `: type`）。frontmatter（服务端 TS）保留不动，Astro 会编译它。
- 验证：重新抓 dev 首页提取脚本，`node --check`/`new Function` 校验纯 JS 语法通过，无 `as`/`!` 残留。告知用户刷新浏览器即可看到 banner/fullscreen 模式下 mp4 淡入淡出循环。
- 经验：**Astro `is:inline` 脚本必须用纯 JS，绝不能写 TS 类型语法**；这类错误 `type-check`/`build` 都发现不了，只能靠浏览器运行时或手动 node 语法校验。

## 决策：主页视频（hf_22.mp4, 30MB）必须外链，不能打包进构建
- 部署现状：当前 **Cloudflare Pages**（`wrangler.jsonc` 的 `assets.directory=./dist`，整 dist 当静态资源上传）；计划未来迁 **Vercel**（`vercel.json`：`outputDirectory=dist`, `framework=astro`）。
- 限制核实（官方文档）：Cloudflare Pages **单资源 ≤ 25 MiB 硬上限** → 30MB 视频打包进 dist 会被拒部署；Vercel 静态产物无严格单文件上限、Hobby 源上传 100MB/Pro 1GB → 30MB 没问题。
- 结论：**同域打包在 Cloudflare 当前就炸，外链 URL 两边都能过且迁 Vercel 零改动 → 选外链**。方案：只外链 30MB mp4，hf_21.jpg（几百 KB）继续本地打包当 poster（不触发 25MiB、同域快）。组件改动：把 `HomeHeroVideo.astro` 的 `import hf22Video` 改成读一个 URL 字符串（建议放配置如 `backgroundWallpaper.heroVideoUrl`），`<video src>` 用外链、`<video poster>` 继续本地 jpg；跨域纯播放无需 CORS。
- 外链宿主候选（待用户拍板）：① Cloudflare R2（已在生态、免流量费、需开 R2+公开桶）；② GitHub Pages 纯资源仓（`user.github.io/assets/hf_22.mp4`，零新服务）；③ Bunny Storage/CDN（媒体最优）。不推荐 YouTube/Vimeo（不能静音自动循环背景播放）、raw.githubusercontent（限流/MIME 不稳）。
